# 実績を使った質問と、外部投稿を参照する下書き

2026-10-10 / `reach-v1`。本体は `gas/src/Reach.js`（GAS上では **Reach.gs**）。新しい定期トリガーや依存パッケージは不要。

## 質問に使う実績

毎回の質問生成でStockから直近90日の測定済み投稿を選ぶ。広告フラグ・有料表示あり、未測定、投稿後48時間未満、14日より古い測定、取り上げない話題を除く。

手動投稿とインタビュー由来を分け、測定経過時間を48〜168 / 169〜720 / 721時間以上の帯に分ける。同群5件以上、中央値の1.3倍以上の上位例がある群から、上位例と中央値付近の比較例をセットで最大3群・6件渡す。帯内にも経過時間の違いがあるため探索用であり、効果の証明ではない。

実際の回答番号に一意に紐づく場合だけ実施済み質問を添える。手動投稿から逆算した質問を、実施した質問や効果が検証済みの教師データにしない。成功投稿の内容を今日の本人の経験へ転用しない。

レイ・セバスチャン・ハンニバルの会議、ミア、質問生成に次の仮説を渡す。

- 読者に身近な話と、本人の航空機開発・経営の見方の意外な接続。
- 現場で迷った選択と、捨てた案・理由・代償の一点。
- 本人固有の場面、予想と現実のずれ、自然な笑い。

一般論へ薄めず、最近の回答・指定テーマ・非公開の意思を優先する。質問モデルは従来の用途別設定に従う。

## 外部投稿の取得と選定

インタビュー開始時に `refreshQuoteSources` が実行される。GASエディタで手動確認する場合も **Reach.gs** を開いて同関数を選ぶ。Slack送信・下書き生成・X投稿は行わない。

`QuoteSources` に原文、投稿ID・著者ID、URL、投稿時刻、観測時刻、公開表示数、前回値・増分・状態を追記する。取得は1日最大1回。新規検索20件と、前回候補の再取得最大20件の計最大2リクエスト（返却投稿は最大40件）に制限する。Xの読取利用枠・課金を使う。API待機中に通常の回答保存ロックは持たない。

直近72時間の投稿から、公開表示数1,000以上、観測30時間以内の候補を最大5件渡す。RT・返信・他投稿の引用、機微指定・閲覧制限、禁止話題、既に質問で使った投稿・自分の保存済み投稿は除外する。保存済み `X_USER_ID` があれば本人の著者IDも除外する。

同じ本文を1時間以上離れた2時点で観測できた場合だけ増分を計算する。増分/観測時間を優先し、初回観測は「表示数上位・伸長は未確認」と明示する。公開表示数には広告を含みうる。人気を内容の正しさや採用効果の証明にしない。

会議で、引用元自体の文脈・主張の根拠と、本人の経験・専門性との接点を検討する。接点の説明を伴う最大1問だけ引用元に紐づける。適切な候補がなければ通常の質問を作る。API権限不足・利用枠切れでもインタビューは続く。同日の追加インタビューでAPIを再試行し続けない。欠落・削除された再取得候補は利用不可として記録する。

## 回答から投稿まで

質問を提示するとき、外部投稿の抜粋と全文リンクもSlackに表示する。本人が答える前に引用元を確認できる。引用元のスナップショットをInterviewsへ保存し、会話・聞き返しにも渡す。引用元付き次問を適応処理で別の問いへ差し替えない。

回答後は従来通り、3人格→ミア→リナ→文脈補完→3人格＋ミア審査→本人承認を通る。外部の主張と本人回答を別々に渡し、本人の賛否・専門的な解釈・体験を本人の口調で編集する。単なる要約・賛同なら見送る。引用元付き回答は1本の短文または長文とし、異なる引用元を統合したり同じ引用元の投稿を分割して量産したりしない。

既定は**参照リンク付き投稿**。本文末尾に検証済みURLをシステムが追加する。短文上限を超えれば長文へ変更し、切断しない。ネイティブ引用とは表示形式が異なる。

[X公式の投稿API資料](https://docs.x.com/x-api/posts/create-post)では、`quote_tweet_id` によるネイティブ引用はEnterprise限定。利用権限を確認した場合だけ `X_NATIVE_QUOTES_ENABLED=true` を設定すると、新規生成分はネイティブ引用になる。承認済みのリンク投稿を設定変更だけで引用形式へ変換しない。

Stockの末尾へ `quote_tweet_id / quote_source / quote_mode / reach_meta`、Interviewsへ `quote_tweet_id / quote_source / reach_meta` を追加。新規セッション・生成時に自動追記する。`edit_meta` と記事用原文履歴にも出典を保持する。管理画面・Slack・Notionで本文と引用元を確認できる。

審査には引用元の本文・URLを渡すが、その人気の数値は渡さない。質問・回答の資料と引用元の対応を検証し、審査待ちの編集は再評価へ戻す。予約・投稿時にも保存資料との一致と参照リンクを確認する。投稿直前の1回の読取で引用元の公開状態・本文を再確認し、削除・編集・確認不能なら公開せず失敗として残す。参照を外した普通の投稿へ自動フォールバックしない。

## 設定と反映

| プロパティ | 既定 | 内容 |
| --- | --- | --- |
| `QUOTE_DISCOVERY_ENABLED` | `true` | 外部候補の取得と質問での使用。falseでも実績を使う通常質問は継続 |
| `QUOTE_SEARCH_QUERY` | 製造・設計・移動・チーム・採用の日本語検索 | X recent searchの検索式 |
| `QUOTE_MIN_IMPRESSIONS` | `1000` | 外部候補の最低公開表示数 |
| `X_NATIVE_QUOTES_ENABLED` | `false` | Enterpriseの引用API権限を確認してからtrue |

次に**新しく作るインタビュー**から適用。進行中の問いや既存ストックは書き換えない。列の手動削除やシートの作り直しは不要。過去の投稿の実績は質問の参考に使うが、採点官の変更・点数による自動承認は行わない。

`reach_meta` は取材仮説、参照した事例ID、引用との接点を投稿まで保持する。今後の実績を質問・編集の版と照合できるが、質問が原因で表示数が伸びたとは断定しない。現在の週次メトリクス取得では厳密な投稿後48時間比較を保証しない。

公式仕様の参照: [recent search](https://docs.x.com/x-api/posts/search/quickstart/recent-search)、[公開表示数と広告の関係](https://docs.x.com/x-api/fundamentals/metrics)。
