# ChatGPT音声取材 → Slack記録 → 既存GASで編集

入口は毎日7:00（Asia/Tokyo）のChatGPTクラウドスケジュール。通知を開き、本人が音声会話を開始する。Slackへ毎朝の質問や会話途中の応答は送らない。終了後の質問・回答の書き起こしと、GASが生成した下書きを同じSlackスレッドに残す。Xの公開は従来どおり本人承認後。

音声のマイク開始・停止は本人操作。約10分または投稿の核3つで終了を提案するが、自動で切断する実装ではない。音声中にSlack連携が使えない場合は、音声終了後のテキスト会話で「Slackに記録して」と指示する。ツールがない場合は未送信と明記し、以下の記録を本人がSlackへ貼り付ける。実際に取得できない会話を再構成・代作しない。

## 現行: AI・ディープテック・テクノロジーの時事コメントを主軸にする

この方針は以前の「判断基準・捨てた案・代償を深掘りする」「実体験につながらないニュースは使わない」より優先する。

- 4問なら3問程度を、直近3日程度のニュースへの感想にする。AI、ロボティクス、半導体・量子計算、宇宙、電池・エネルギー・新素材、先端モビリティ、バイオ技術から、短い説明でコメントできる題材を選ぶ。同じ出来事は繰り返さない。
- 芸能・映画・スポーツ・流行商品は話題性だけで選ばない。技術の変化が主題の応用事例は可。AIの20%上限は廃止し、AI以外の技術も材料に応じて選ぶ。
- ニュースの対象と何が起きたかを一文で伝えてから、気になる点・期待・違和感を一つ聞く。一度に複数の問いを投げず、知らない・難しい・話せない話題は次へ進む。
- 専門的な題材も背景を説明して扱う。ただし、専門知識の試験、抽象的な経営判断・資源配分・代償、機密・社内事情が必要な問いは避ける。本人が自発的に話した深い内容は残す。
- 本人の経験やテトラとのつながりは必須にしない。本人の感想が主役なら時事コメントも編集対象。採用や会社紹介へ無理に結びつけない。
- 出典・掲載日を確認し、見出しだけでは分からない数字や因果を補わない。適切なニュースがないときは創作せず、最近使ったAIや試したい技術への感想を聞く。ニュースの紹介と本人の回答を分ける。
- 追問は話したそうな点について一つだけ。短答を失敗扱いせず、投稿では本人の口調と留保を残す。既存の複数人格審査・引用照合・本人の公開承認は維持する。

以前の時事コメント方針は既存タスク「毎朝7時・teTra音声インタビュー」に保存済み。今回の技術重視方針は別途タスクの保存指示も更新する必要がある。リポジトリの更新だけでタスクが変更されたとは扱わない。

### 毎朝7時のChatGPT取材に追加する指示

次の段落を既存タスクの取材方針として追加する。既存の時刻・音声開始・終了条件・Slack記録形式は維持する。**GASのデプロイだけではChatGPTの保存済みタスクは更新されない。**

> 今後の取材は、SNSで公開できてコメントしやすい時事ネタを中心にする。4問なら3問程度を目安に、直近3日程度のニュースを出典・日付を確認して選ぶ。AI・ディープテック・テクノロジーを主軸にする。AIの進歩や実装、ロボティクス、半導体・量子計算、宇宙、電池・エネルギー・新素材、先端モビリティ、バイオ技術から分野を変える。芸能・映画・スポーツ・流行商品は話題性だけでは選ばない。技術の変化が主題なら娯楽分野への応用も扱える。研究成果・企業発表・実証・販売開始は区別する。ニュースを一文で説明してから「どこが気になりますか」など感想を一つだけ聞く。ニュースを知っている前提にしない。当事者でない意思決定や二択を押し付けず、質問の言い換えでも別のニュースを混同しない。技術の難しさだけで題材を避けず、平易に説明する。ただし専門知識の試験や、経営の判断基準・資源配分・捨てた案・代償の言語化、機密や社内事情が必要な問いは避ける。本人の実体験やテトラとの接点は必須にせず、採用・宣伝・教訓へ無理につなげない。短い感想も材料として認める。知らない・難しい・話せないなら別の話題へ進む。追問は本人がさらに話したそうな点の理由を一つだけ。ニュースを取得できない、出典や日付を確認できない、適切な題材が足りない場合はその旨を伝え、最近使ったAIや試したい技術への感想を聞く。最新ニュースを創作しない。本人が自発的に長く話した内容は削らず、口調と留保を保って記録する。レイ・セバスチャン・ハンニバルの検討とミアの編集判断にもこの方針を優先し、深い検討は編集側で行う。以前の深掘り優先指示と矛盾する場合はこの方針を優先する。

ニュースの短い紹介と出典・掲載日は【質問】に含める。本人の発言だけを【回答】へ記録し、未確認のニュースやAIの補足を本人の事実として保存しない。

## ChatGPTへの受け渡し指示

保存先は `#corp_pr_x-autopost_nakai`。Slack連携でチャンネルを検索してIDを取得する。会話が完了してから、実際の質問と本人の回答の書き起こしを以下の**普通のテキスト**で送る。見出しや行を太字・引用・コードブロックにしない。音声ファイル自体の原文ではなく、認識された書き起こしである。

```text
【音声インタビュー記録 v1】
記録ID: voice-20261028-0700-a1
分割: 1/2
質問番号: 1
【質問】
実際に聞いた質問文
【回答】
実際の本人の発言の書き起こし。そのままの口調と段落を残す。
【記録完了】
```

```text
【音声インタビュー記録 v1】
記録ID: voice-20261028-0700-a1
分割: 2/2
質問番号: 2
【質問】
次に実際に聞いた質問文
【回答】
その質問への本人の発言の書き起こし。
【確認会話・原文】
本人: どういう意味？
聞き手: 実際に説明した内容（取得できる場合だけ記録）
【AIメモ・原文ではない】
必要なら取材の要約。本人の回答へ混ぜない。
【記録完了】
```

- 上の例の内容を実際の会話へ置き換える。サンプル自体を送らない。
- 取材終了後に全体の分割数を確定する。記録IDは取材ごとに一意にし、全パートで同じ値（英数字・ハイフン・アンダースコア8〜64文字）を使う。
- 1メッセージ4500文字以内、目安3500文字。1メッセージに質問と回答は各一つ。質問番号は1から順番、分割番号は全体で1から順番。最大30パート・20質問。
- 長い回答は段落の境界で複数パートへ分割する。質問番号と質問文を同じにして続きの回答を送る。GASはその続きだけ改行で結合する。改稿・要約して短くしない。単一回答の合計は40000文字まで。
- 最初の記録をチャンネル直下へ送り、返された親メッセージの `thread_ts` に残りを返信する。別スレッドへ散らさない。送信した各メッセージのリンクを確認し、送信に失敗したら未送信パートを明示する。
- 聞き返し、質問の意味の説明、AIの解釈は任意の確認会話欄へ。回答として保存するのは本人の実質的な回答だけ。AIメモと確認会話はGASの生成資料へ入らず、SlackとVoiceImports.raw_textに残る。
- 回答に予約された見出し文字列が独立行で出る場合は、勝手に原文を変えずに保存前に知らせる。パーサーは曖昧な記録を拒否する。
- Slack連携が `【記録完了】` の後に自動追加する `*使用して送信されました* <@ユーザーID|ChatGPT>` と英語の `*Sent using* <@ユーザーID|ChatGPT>` は取り込み側で署名として扱う。削除や再送の操作は不要。署名を含む受信本文はraw_textへ残し、質問・回答の本文は変えない。任意の後書きや複数記録の混在を許可する変更ではない。
- APIキー、管理画面のトークン、認証情報を記録へ入れない。本人が非公開とした話は回答欄へ送らない。
- AIの参考投稿をこの記録へ混ぜない。GASの編集会議→ミア→リナ→構成検証→品質ゲート→本人承認の工程に渡す。

## 引用元URLの記録（2026-11-03）

X投稿を話題にした質問では、【回答】の後・任意の確認会話/AIメモより前に次の2行を追加する。引用がない質問は欄ごと省略。本文の原文とURLを混ぜない。ニュース記事URLはこの欄ではなく質問の出典に残す。

```text
【引用元URL】
https://x.com/example/status/1234567890123456789
```

同じ回答を複数パートへ分割した場合は全パートへ同じURLを付ける。実在を確認した元のX投稿1件だけを指定し、URL/投稿IDを創作しない。外部原文の全文を本人回答に転記しない。GASが回答保存後に原文を読取APIで取得し、別資料として編集・審査へ渡す。取得失敗時は回答を保持して再生成できる。新規引用付き稿は本人の意見と引用URLの組み合わせ。詳細は [現行仕様](impressions-first.md)。

## GAS側

`gas/src/ChatGPTInterview.js` → GASエディタ **ChatGPTInterview.gs**。

ChatGPTの毎日7時スケジュールが作成できた後で、`setupChatGPTVoiceInterview` を一度実行する。VoiceImports表とInterviews末尾の出典種別/記録ID列を追加し、5分ごとに1取材を処理するトリガーを追加する。既存トリガーや取材を消さず、`INTERVIEW_ENTRYPOINT=chatgpt_voice` によりSlackの定期・追加質問を停止する。既存Slackスレッドへの途中回答は保持し、従来どおり継続できる。

`doPost` は対象チャンネルの完了記録を保存するだけでLLMを呼ばない。全パートが揃うまで待ち、同一記録ID・分割番号は重複保存しない。別本文での同一ID再利用は拒否する。`processVoiceInterviewRecords` が原文をInterviewsへ入れ、既存の `generateDraftsFromInterview` を実行して同じスレッドへ下書きを返す。採点は夜の品質ゲートで行う。AIメモ・確認会話は一次回答にしない。

`voiceRecordPayload` は **ChatGPTInterview.gs** 内の署名除外ヘルパーで、手動実行は不要。署名の有無だけが違う再配送は同一本文として扱い、最初に保存したraw_textを保持する。

人の投稿を従来の対象チャンネル内で受け付ける。bot投稿は既定では受け付けない。ChatGPT連携がbotとして送信する環境では、実際に送信されたメッセージのbot IDを確認し、`CHATGPT_SLACK_BOT_ID` にそのIDだけ設定する。全botの許可はしない。未設定時は本人が同じ記録を貼り付ける運用で取り込める。Slackイベントの受信権限・対象チャンネル参加は従来と同じ。

VoiceImportsの `status` は `received` → `running` → `done` / `no_material` / `failed`。失敗・7分超の中断は自動で無限再試行しない。未生成の原文は保持する。下書き0件で失敗した取材の再生成は **Interview.gs** の `regenerateFailedInterviews`、一括は **InterviewRecovery.gs** の `startFailedInterviewBatch`。生成中はOPENなので旧回復バッチから除外する。手動再生成の結果はVoiceImportsの完了状態を更新しないため、StockとLogを確認する。

`restoreSlackInterviewEntry` でSlackの定期取材へ切り戻せる。ChatGPT側の通知も止める場合はChatGPTのスケジュールを一時停止する。記録・下書きは削除しない。

## 検証境界

自動テストは分割欠落・重複・原文保持・要約分離・編集工程への受け渡し・ロック解放・期限切れの保留を検証する。実際のスマホ/PCの音声UI、音声からテキストへの引き継ぎ、Slack連携の投稿主体、Slackイベントの実到達は最初の本人取材で確認する。取材をしていない状態で架空の回答を本番へ送って検証しない。
