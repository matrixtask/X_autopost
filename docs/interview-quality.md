# 質問・受け答えの品質改善（2026-09-10）

**現行追記（2026-09-11）:** [生成前の編集会議](editorial-council.md)を実装。人格は設計時だけでなく、初回質問・各会話応答・回答からの投稿生成の前にも使う。3人格の確定意見→ミアの内省→生成を別APIに分ける。以下の初版記録より、この追記を優先する。「考え込む質問は価値ゼロ」は撤回し、判断の深掘りを次の予定質問と置き換えられる。本文の核の完全一致検証と、末尾の機械切断の廃止を追加。APIの費用・待ち時間は増える。最新テスト103件通過。

目的は、本人が少ない往復で話せる一次情報を増やし、本人の言葉で投稿できる材料を得ること。
質問数、回答文字数、LLMの合格点だけを成果とはしない。

## 3人の議論

以下は架空の視点による設計議論。実在の専門家の検証や推薦ではない。

| 視点 | 主張 | 異論・修正 |
| --- | --- | --- |
| レイ：技術・証拠を重視する戦略参謀 | 聞き返しを回答扱いにする制御を先に直す。原文を保存してから会話を補助する | 状態を増やすなら、追問のスキップ、最終問、失敗復帰までテストする |
| セバスチャン：本人の負担と信頼を重視 | 不足1点だけ聞く。知らない・話せないときに掘り続けない | 毎回答の要約・褒め言葉や必須の追問には反対。初版は追問1回まで |
| ハンニバル：敗北を内省した軍師、外部投資家・メンターの視点 | 最終目的を見据え、本人固有の判断・失敗条件・資源配分を拾う | 長文や自己採点の合格数を成功とみなすと循環する。追加返信の負担も測る |

合意は、回答の長短による良問・悪問ラベルを外すこと、質問への本人メモの反映、
聞き返しでは現問を保持すること、追問は1セッション最大1回、材料不足なら0案を許すこと。
深掘りの量には意見が分かれたが、まず負担を制限して評価する。

## ミアによる内省と決定

ミアは「イーロン直属のSNS担当・若手女性」というユーザー指定の創作設定。
実在の人物・チームとの関係や、Xの内部情報を持つという意味ではない。

> 回答の長さを競わせても、その人をフォローする理由は生まれない。
> 本人の判断や意外な事実が出た瞬間だけ、もう一つ聞く。

最初の案の弱点は、「具体性を増やす」を理由に毎回深掘りしてしまうことだった。
そこで、十分なら次へ進み、すでに否定された前提を次問でも繰り返さない設計を採用した。
人格は設計レビューにだけ使う。投稿者の人格やVoiceの文体を置き換えない。

## 実装した挙動

- 初回の質問生成に、本人の質問・会話の希望、直近30問、回答済みQ/Aを渡す。
  メモ中のURLや一部の操作語は除外する。過去メモを今日の出来事の証拠にしない。
- スキップは理由未確定の見直し材料。短答を失敗、長答を成功と分類しない。
  投稿から逆算した質問は、実施して効果を測った質問ではなく参考例と明記する。
- 初回質問の空欄・不正型・未指定テーマ/カテゴリ・同文重複を除外する。
  有効な質問が0件なら既存の開始失敗処理へ戻す。
- 回答原文を先に保存。Claudeが返す受領用の抜粋は、40字以内かつ原文との完全一致を検証する。
- 必要な不足情報だけ1問聞く。追問はセッション全体で最大1回、飛ばしても元回答は残る。
  追問の回答も下書き・リライトの一次資料へ渡す。
- 次の予定質問が回答済みの内容や否定された前提を繰り返す場合、同じテーマ内で修正する。
- 「どういう意味？」「それってどういう意味？」「質問を言い換えて」等の明示的な聞き返しは、
  同じ質問を言い換え、回答を消費しない。「メモ: …」も現問を保持する。
- 「終了」「以上」「おわり」「done」は完全一致で終了。「以上の理由で…」は通常の回答。
  「スキップ」「次の質問」「次へ」で今の質問・補足を飛ばせる。
- 「訂正: …」「修正: …」は次問の素材として誤記録しない。過去回答の自動訂正は未実装。
- LLMの不正出力・API失敗は保存済み原文と予定質問で進行する。メモ参照失敗も記録して継続する。
- 同時返信はロックで二重処理を防ぐ。処理中の返信は未記録であることを通知し、再送を案内する。
- 下書きの `qi` は回答済みの実在行だけ受け付け、テーマ・カテゴリ・画像もその行から引き継ぐ。
  質問に含まれる前提や見本を本人の事実にしないよう指示する。
- 材料不足の `[]` は `no_material` として記録。再生成で繰り返さない。
  非空なのに不正案しかない出力はエラーとして区別する。進行中・追問待ちも再生成対象外。

会話例（テスト用の架空例。実際のLLM生成結果ではない）:

| 場面 | 期待する振る舞い |
| --- | --- |
| 「3kg軽量化した」 | 短いことを理由に低品質扱いしない。必要な場合だけ「何を変えた？」 |
| 「どういう意味？」 | 現問を言い換える。次の質問へ進めない |
| 「その番組は見ていない」 | 好きな登場人物を聞く予定質問を、答えられる切り口へ変える |
| 補足に「スキップ」 | 元の回答を残し、次問または生成へ進む |
| 「特にない」のみ | 材料がなければ0案。架空の体験を作らない |

外部APIを呼ばないNode/VMテストで、原文の保存順、状態遷移、失敗復帰、
出典検証、追問のリライト参照、材料不足の再処理防止を確認した。

本番データは読み取りのみで確認した。確認範囲は InterviewsのID列 A1:A1000
（最終記録721行）、直近60問 A662:K721、Memory A1:D60。
実際に、同じ答えを求める質問や、知らないと答えた前提を繰り返す質問を確認した。
空欄は未回答という事実にとどまり、悪問や離脱の原因と断定していない。
実データの原文や認証情報は、この文書やテストへ転記していない。

GAS/Slackでの実応答、生成文の品質改善、プロフィールクリック・フォロワー増への効果は未検証。
質問の意味的な重複、非公開意思の解釈、事実の保持はプロンプトにも依存し、完全保証はできない。
聞き返しの判定は明示的な表現を対象にしたもの。自由文全般の意図分類や過去投稿の訂正ではない。

反映後の最初の10セッションを、可能なら変更前10セッションと同じ観点で人がレビューする:

1. 公開可能な本人固有の事実・判断を得られたか。
2. 既知情報の再質問、誤った前提、本人の訂正が何件あったか。
3. 補足の要求/回答/スキップ件数と、追加返信の負担。
4. 本人による事実修正なしで使える下書きの割合。

これは運用品質の確認で、質問の因果効果の証明ではない。
下流の成果は既存の計測経過・ホールドアウト方針に沿ってプロフィールクリック率等を確認する。
採点モデル・軸の重み・自動承認設定はこの変更では変えていない。

## 反映・切り戻し

ユーザーのUbuntu環境:

```bash
cd ~/X_autopost && git pull origin main && cd gas && ./deploy.sh
```

GASエディタで `Sheets.gs` を開き、`setupSpreadsheet` を1回実行する。
Interviews末尾に `followup_question` / `followup_answer` / `followup_answered_at` を追加する。
最初の追問時にも自動追加するが、反映時のセットアップで確認しておく。
Slack受信はバージョン付きWebアプリなので、B（Slack）のデプロイ更新が必要。
`.deployment-id-slack` が登録されていれば `deploy.sh` が更新する。

新規関数はすべて `gas/src/Interview.js` → GASの `Interview.gs` に入る内部ヘルパー:
`buildInterviewMemoryPrompt`、`validInterviewQuestion`、`hasPendingFollowup`、
`interviewAnswerText`、`planInterviewTurn`、`handleInterviewReplyLocked`。
引数付きヘルパーをGASのプルダウンから手動実行する必要はない。

追問を止める場合はスクリプトプロパティ `INTERVIEW_FOLLOWUP_ENABLED=false`。
既に出した追問への返信は引き続き処理する。次問の適応や聞き返しは維持される。
変更全体を戻す場合は該当コミットを `git revert` して同じ手順で反映する。
追加列は削除しない。追問待ちがある場合は完了/スキップしてから戻す。
