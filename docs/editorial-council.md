# 本人の面白さを薄めない編集会議

2026-09-12追記: 長文回答は[リナによる形式選択・編集](long-answer-editing.md)へ進む。短文の文字数超過と、明示的に選んだ長文形式を区別し、編集後にも3人格＋ミアの構成審査を行う。以下の導入時記録にある「長文の棄却」は、短文形式の上限超過を指す。

2026-09-11。対象は初回インタビュー質問、聞き手の応答・追問・次問、インタビュー回答からの投稿生成。テーマ一覧と新5軸の採点は保持する。採用成果の向上は仮説であり、この変更で実証済みとは扱わない。

## 3人格の議論と確定意見

人格は架空の視点。実在の独立した専門家・社員による検証ではない。

| 人格 | 確定意見 | 他者への異論・採用条件 |
| --- | --- | --- |
| レイ：冷静・論理的な戦略参謀 | 判断理由、捨てた案、代償、留保を原文から拾い、編集後も残す | 「読者なら普通こう思う」を本人の事実にしない。趣味に採用を後付けしない |
| セバスチャン：候補者の信頼と組織運営を重視する執事 | 候補者が仕事の面白さ・難しさ・任せ方を想像できる取材にする | 驚きの最大化だけに反対。初見向けの説明は残す。質問数で負担を守り、少し考える余地を認める |
| ハンニバル：敗北を内省して転生した軍師、外部投資家・メンターの視点も持つ | 予想と現実の差、最終目的、資源配分、組織、相手の適応を問い直す。成立条件・代償・失敗経路・方針転換条件まで考える | 局地的な成功だけで勝利を保証しない。採用CTAの強制に反対。予想は仮説と区別する |

合意は「答えやすい入口から具体的な選択へ」「全投稿を採用PRにしない」「本人の原文の核を消さない」。深掘りの負担は追加問を増やすのでなく次の予定質問を置き換えて抑える。

## ミアの内省と決定

ミアは「イーロンの広報担当の若手女性」をモデルにした架空の編集責任者。実在の所属・経験・推薦は主張しない。

きれいに短く要約する編集が、本人の引っかかる比喩や判断を消していた。採用するのは、3人が見つけた固有の選択・意外な具体・候補者への手掛かり。退けるのは、後付けの教訓・逆張り・根拠のない仕事や裁量の約束。本人の答えそのものは生成しない。

## 実行する順序

1. 会議API：3人の提案、互いへの異論、各人の確定意見、合意と残る異論を短い構造化データにする。重複人格・欠損は不受理。
2. 内省API：ミアが確定意見を受け、採用・不採用・編集方針・聞く不足一点を決める。投稿の場合は回答番号 `qi` と回答に完全一致する核の引用を選ぶ。回答原文には主回答と補足回答だけを使い、質問や文体見本は混ぜない。
3. 生成API：初めて質問・聞き手の応答・投稿を作る。投稿は選んだ核を `core_quote` と本文にそのまま保持する。本文から核が消えた案、別回答の核、文字数超過案は保存しない。材料がない場合は0案。

3人は1モデル内でシミュレートする。各人格の独立APIや実在人物のレビューとは異なる。構造はコードで確認できるが、異論の有用性、引用の意味的な適切さ、投稿の面白さはモデルにも依存する。逐語的な内部思考を記録せず、短い外向け編集判断を残す。

会議と内省の記録は既存の `Log` シートの `editorial_council` イベントに保存する。`context_id` と `brief.stage` で対象を識別する。初回質問はセッション作成前なので `initial`。投稿・会話はセッションIDを含む。原文引用を含みうるため、公開用ログではない。Logの追加列は不要。

## 質問と編集の例

以下は設計上の例で、本人の実回答や実APIの生成結果ではない。

- 入口：「最近、試作で決めたことはありますか？」
- 回答に複数の案が出た後：「もう一つの案を見送った理由は何ですか？」
- 機体を見た人の感想が出た後：「作る側が気にしていた点と、違いはありました？」
- 四人乗りを望む声が出た後：「その要望には、今どう答えていますか？」

仮想回答「完成より、まず壊れる条件を知りたい。まだ試す前です。」なら、後者の留保も含めた固有の判断を残す。「安全と品質を大切にします」というどの会社にも言える結論に置き換えない。原文にない逆張りや社員への権限を足さない。

## 時間予算と失敗

通常は従来の生成1回に対して会議・内省の2回が増える。各会議3500・内省3000トークンを上限として指定し、JSON回復時は既存の上限内で増枠する。単純に費用が3倍とは限らないが、費用と待ち時間は増える。

最初の会議から同じGAS実行に240秒の共通期限を持たせる。APIとJSON再試行の入口で残60秒を確保できなければ追加呼び出しを止める。採点開始に残120秒がなければ保存済み下書きの採点は夜の既存ゲートへ回す。失敗セッションの再生成は既定1セッション、残時間を見て次セッションを停止する。ネットワーク要求自体は強制中断できず、実モデルの遅延はデプロイ後に確認が必要。

会議が失敗したまま通常生成へ黙って戻さない。会話では既に保存した回答を維持し、用意済み質問で進むことを通知する。投稿生成失敗は完了セッションの回答を残す。復旧は既存の **Interview.gs** の `regenerateFailedInterviews`（既定1セッション）。既に投稿があるセッションを重複生成する関数ではない。

手動の文体一括リライト `Rewrite.js` と旧 `QUALITY_MODE=legacy` の採点リライトは今回の会議導入対象外。インタビューからの生成はモードにかかわらず会議を通る。採点モデルはClaudeのまま。質問・会議・内省・投稿は用途別ルーティングにより既定OpenAI。
